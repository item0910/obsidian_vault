## MySQL 组件

### 连接器

负责: 跟客户建立连接, 获取权限, 维持和管理连接.

- 连接命令一般这样写

```sh
mysql -h$ip -P$port -u$user -p
```

- 连接空闲
![[附件/image/01_MySQL组件-一条查询语句的执行流程-1.jpg]]
- 连接超时断开

> 通常, 连接的建立过程是比较复杂的, 所以尽量要减少建立连接的动作, 也就是尽量使用长连接 (数据库连接池)[[01_JDBC#8 1 JDBC 数据库连接池的必要性]]

- MySQL 异常重启?
    - 执行过程中, 临时使用的内存是管理在连接对象中的, 如果不断开就一直不会释放, 导致对象过大, 造成 OOM , 被系统强行杀死, 在现象上就表现为, MySQL 异常重启.
    - 如何解决:
        1. 定期断开长连接, 或者在判断执行过一个占用内存比较大的操作之后, 就重连
        2. 5.7 后的版本可以通过 `mysql_reset_connection` 来初始化链接资源, 恢复到刚建完连接的状态. 不需要重连和做权限验证.

### 查询缓存

MySQL 会在拿到请求后看看缓存是不是执行过这条语句. 如果有结果则直接返回.
但为什么大多数时候建议不要开启缓存呢?
- 只要对一个表进行更新, 所有缓存都要清理. 导致缓存命中率非常低.
- 设置: 你可以将参数 `query_cache_type` 设置成 DEMAND, 这样默认的请求都不会使用缓存. 确定要使用缓存的, 可以像下面这个语句:

    ```
    mysql> select SQL_CACHE * from T where ID=10；
    ```

- 8.0 之后, 缓存模块整个删去了.

### 分析器

```sql
mysql> elect * from t where ID=1;

ERROR 1064 (42000): You have an error in your SQL syntax; check the manual that corresponds to your MySQL server version for the right syntax to use near 'elect * from t where ID=1' at line 1
```

- 词法分析: 词用的对不对
- 语法分析: MySQL 语法对不对.
一般第一个错误都会标注在 "use near" 附近, 所以需要关注这一点

### 优化器

```sql
mysql> select * from t1 join t2 using(ID) where t1.c=10 and t2.d=20;
```

- 优化器决定如何优化搜索你的语句, 比如表里有多个索引的时候, 用哪个索引; 或者有 join 的时候, 决定表的连接顺序.

```sql
mysql> select * from t1 join t2 using(ID)  where t1.c=10 and t2.d=20;
```

- 经过优化后, 执行方案就确定下来了.

### 执行器

- 开始执行, 判断是否有权限.
- 如果有, 就会使用这个表的引擎提供的接口.
- 返回结果给客户端 (如果在缓存中查询, 权限会在返回结果的时候进行核查.)
- 你会在数据库的慢查询日志中看到一个 `rows_examined` 的字段，表示这个语句执行过程中扫描了多少行。这个值就是在执行器每次调用引擎获取数据行的时候累加的。

### 总结

本节只需要对流程有一个初步的了解.

## 学后思考

- 如果表 T 中没有字段 k， 而你执行了这个语句 `select * from T where k=1`, 那肯定是会报“不存在这个列”的错误： “Unknown column ‘k’ in ‘where clause’”。 你觉得这个错误是在我们上面提到的哪个阶段报出来的呢？
    - 字段不是数据, 是不需要打开表就能获得, 于是排除执行器阶段.
    - 答案: 分析器, 分析器分为语法解析器和预处理两个模块, 前者看语法是否正确, 后者看字段是否合法. ^ba69b0
- 评论区的一个逻辑小品:
    - 有人建了一个没有权限的用户来执行找 k 操作, 结果返回的是 " 没有权限 ", 所以他感觉是在执行器才进行判断的.
    - 其实这个是 MySQL 的安全问题 (告诉你 k 不存在已经算信息了), 合理的逻辑是: 分析器先看看 k 存不存在 -> 执行器看看你有没有权限知道这个信息 -> 返回信息.
