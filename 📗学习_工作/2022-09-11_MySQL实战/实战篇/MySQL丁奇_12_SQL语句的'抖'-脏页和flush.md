## 前言

当内存数据页跟磁盘数据页内容不一致的时候，我们称这个内存页为“脏页”。内存数据写入到磁盘后，内存和磁盘上的数据页的内容就一致了，称为“干净页”。

抖的那一下, 可能就是在刷脏页

## SQL 语句的 ' 抖 '- 脏页和 flush

### SQL 语句为什么变慢了

1. 场景 1, redo log 写满
![[附件/image/12_SQL语句的'抖'-脏页和flush-1663265725042.jpeg]]
cp' - cp 之间就是要刷的脏页
2. 场景 2, 内存不足, 需要淘汰一些数据页, 留给其它数据页使用. 如果淘汰的是脏页, 那么就要写到磁盘.
3. 场景 3, MySQL 认为现在是闲时, 见缝插针安排刷盘.
4. 场景 4, MySQL 正常关闭, 进行刷盘.

3,4 对应的是闲时, 对性能影响不大, 所以我们讨论 1,2 对性能的影响

#### 分析 1,2 场景对性能的影响.

1. redo log 写满了, 要 flush 脏页, 这种情况要尽量避免, 因为此时的更新能力为 0;
2. 第二种是内存不够了, 要将脏页先写到磁盘. 这种情况其实是常态. 因为 InnoDB 倾向于先使用内存.

InnoDB 的策略是尽量使用内存，因此对于一个长时间运行的库来说，未被使用的页面很少。

而当要读入的数据页没有在内存的时候，就必须到缓冲池中申请一个数据页。这时候只能把最久

不使用的数据页从内存中淘汰掉：如果要淘汰的是一个干净页，就直接释放出来复用；但如果是脏页呢，就必须将脏页先刷到磁盘，变成干净页后才能复用。

所以，刷脏页虽然是常态，但是出现以下这两种情况，都是会明显影响性能的：

1. 一个查询要淘汰的脏页个数太多，会导致查询的响应时间明显变长；

2. 日志写满，更新全部堵住，写性能跌为 0，这种情况对敏感业务来说，是不能接受的。

所以，InnoDB 需要有控制脏页比例的机制，来尽量避免上面的这两种情况。

### InnoDB 刷脏页的控制策略

首先, 告诉 InnoDB 你的主机 IO 性能, 通过 fio 工具来测试磁盘的 IOPS, 然后设置这个参数. innodb_io_capacity

```shell
 fio -filename=$filename -direct=1 -iodepth 1 -thread -rw=randrw -ioengine=psync -bs=16k -size=500M -numjobs=10 -runtime=10 -group_reporting -name=mytest 
```

我们设置的参数, 目的是为了改变刷脏页的频率, 达到与机器性能匹配又满足业务需求

InnoDB 会计算两个数值: F1(M) 和 F2(N)

- F1(M):
参数 innodb_max_dirty_pages_pct 是脏页比例上限，默认值是 75%。InnoDB 会根据当前的脏页比例（假设为 M），算出一个范围在 0 到 100 之间的数字，

```mysql
F1(M)
{
  if M>=innodb_max_dirty_pages_pct then
      return 100;
  return 100*M/innodb_max_dirty_pages_pct;
}
```

(逻辑就是看看现在预设的脏页比例承受的住吗?如果承受不住就拉满, 承受的住就承受着)

- F2(N)
InnoDB 每次写入的日志都有一个序号，当前写入的序号跟 checkpoint 对应的序号之间的差值，我们假设为 N。InnoDB 会根据这个 N 算出一个范围在 0 到 100 之间的数字，这个计算公式可以记为 F2(N)。F2(N) 算法比较复杂，你只要知道 N 越大，算出来的值越大就好了。 (逻辑就是现在的 redo log 还有空间写吗? 如果没有了, 就要赶紧拉满刷脏页)

根据上述算得的 F1(M) 和 F2(N) 两个值，取其中较大的值记为 R，之后引擎就可以按照 innodb_io_capacity 定义的能力乘以 R% 来控制刷脏页的速度。

要尽量避免 " 抖 " 这种情况，你就要合理地设置 innodb_io_capacity 的值，并且平时要多关注脏页比例，不要让它经常接近 75%。

- 一个有趣的策略:
MySQL 在刷赃页时, 会看看他的邻居是不是也是脏页, 如果是, 就会拉着一起刷, 这个过程会传递下去. 这个机制可以减少很多随机 IO, 在机械硬盘时代是有意义的, 但是 SSD 就没有意义.

我们可以通过 innodb_flush_neighbors 参数就是用来控制这个行为的，值为 1 的时候会有上述的“连坐”机制，值为 0 时表示不找邻居，自己刷自己的。

在 MySQL 8.0 中，innodb_flush_neighbors 参数的默认值已经是 0 了。

### 小结

1. 从一个命令为什么会 " 抖 ", 理解了 InnoDB 刷赃页的行为
2. InnoDB 会在 4 个情况下刷脏页, 分别是 redo log 写满, 内存写满, 闲时和 MySQL 正常关闭时.
3. 我们可以通过机器性能, 合理设置参数, 来控制刷脏页的性能
4. MySQL 有拉邻居脏页一起刷的策略, 如果存储设备是 SSD , 可以通过参数关闭.

- 一个内存配置为 128GB、innodb_io_capacity 设置为 20000 的大规格实例，正常会建议你将 redo log 设置成 4 个 1GB 的文件。
  但如果你在配置的时候不慎将 redo log 设置成了 1 个 100M 的文件，会发生什么情况呢？又为什么会出现这样的情况呢？
  - 答: redo log 很快被写满, 可以发现磁盘压力很小, 但是数据库性能抖动 (间歇性下跌)
