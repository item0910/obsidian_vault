# 一. JVM 虚拟机与 Java 体系结构

**JVM 虚拟机**; **Java**

## 1. JVM 的跨平台特点

### 为什么 Java 可以跨平台


正是因为 java 虚拟机的存在, 才使得 java 可以跨平台, 只要将 java 编译生成的字节码文件 ([[JVM宋红康_中篇01_.class文件结构]]) 传输给虚拟机, 即可实现 java 程序在不同系统中的运行, 具体的实现细节由 java 虚拟机掌握

### 虚拟机与 java 虚拟机

1. 虚拟机是什么

	所谓虚拟机, 就是对物理计算机的仿真, 它专为执行单个计算机程序所设计

2. java 虚拟机是什么
	java 虚拟机与 java 语言没有必然的联系, 它只与特定的二进制文件格式—— class 文件格式所关联 ([[JVM宋红康_中篇03_类的加载过程详解#3 1 验证Verification]])
	所有的 java 程序都运行在 java 虚拟机的内部, 而 java 虚拟机, 就是**二进制字节码的运行环境** 负责装载字节码到其内部, 解释编译字节码指令为机器指令执行, 解释为如何取操作数, 怎么处理操作数, 结果放在哪里

4. 目标
	使各语言之间的交互不再存在困难, 像使用原生 API 一样方便, java 虚拟机正向着 " 多语言虚拟机方向发展 "

## 5. JVM 的架构模型

Java 编译器输入的指令流基本上是一种基于栈的指令集架构,另外一种指令集架构则是基于寄存器的指令集架构。

- 具体来说: 这两种架构之间的区别:
	- 基于栈式架构的特点
		- 设计和实现更简单,适用于资源受限的系统;
		- 避开了寄存器的分配难题: 使用零地址指令方式分配。
		- 指令流中的指令大部分是零地址指令,其执行过程依赖于操作栈。指令集更小,编译器容易实现。
		- 不需要硬件支持,可移植性更好,更好实现跨平台

	- 基于寄存器架构的特点
		- 典型的应用是 x86 的二进制指令集: 比如传统的 PC 以及 Android 的 Davlik 虚拟机。
		- 指令集架构则完全依赖硬件,可移植性差
		- 性能优秀和执行更高效;
		- 花费更少的指令去完成一项操作。
		- 在大部分情况下,基于寄存器架构的指令集往往都以一地址指令、二地址指令和三地址指令为主,而基于栈式架构的指令集却是以零地址指令为主。

几个名词解释:

- 栈架构:
	- 设计简单: 因为是针对栈的操作, 只存在入栈和出栈
	- 零地址指令方式: 因为方法只做入栈出栈操作, 只需关心操作数而不需要关心地址
	- 指令更小: 8 位指令
	- 不需要硬件支持: 栈是基于内存的, 不需要考虑硬件结构

- 寄存器架构:
	- 指令大:16 位指令
	- 指令少

由于跨平台特性, java 的指令都是根据栈来设计的

## 6. JVM 的生命周期

### 启动 ->

- 虚拟机的启动

Java 虚拟机的启动是通过引导类加载器 (bootstrap class loader) 创建一个初始类 (initial class) 来完成的,这个类是由虚拟机的具体实现指定的。

[[JVM宋红康_上篇02_类加载子系统]]

### 执行 ->

- 虚拟机的执行
	- 一个运行中的 Java 虚拟机有着一个清晰的任务: 执行 Java 程序。
    - 程序开始执行时他才运行,程序结束时他就停止。
    - 执行一个所谓的 Java 程序的时候,真真正正在执行的是一个叫做 Java 虚拟机的进程。

### 退出<<

虚拟机的退出有如下的几种情况：
- 程序正常执行结束
- 程序在执行过程中遇到了异常或错误而异常终止
- 由于操作系统出现错误而导致 Java 虚拟机进程终止
- 某线程调用 Runtime 类或 System 类的 exit 方法，或 Runtime 类的 halt 方法，并且 Java 安全管理器也允许这次 exit 或 halt 操作。
- 除此之外，JNI(Java Native Interface) 规范描述了用 JNIInvocation API 来加载或卸载 Java 虚拟机时，Java 虚拟机的退出情况。
