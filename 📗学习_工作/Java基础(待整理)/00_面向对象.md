# 面向对象

Java 语言是如何处理 Java 程序中类, 实例对象 和 彼此之间的关系的

## 1. 面向对象的基本概念: 类与对象

- 类是对一类事物的描述, 是抽象的, 概念上的定义
- 对象是实际存在的该类事物的个体, 因而也被称为实例

## 2. 面向对象相关的关键字

### 2.1 权限修饰符

- 四种权限修饰符

| 修饰符    | 类内部 | 同一个包 | 不同包的子类 | 同一个工程 |
|:--------- | ------ | -------- | ------------ |:---------- |
| private   | Yes    |          |              |            |
| (缺省)    | Yes    | Yes      |              |            |
| protected | Yes    | Yes      | Yes          |            |
| public    | Yes    | Yes      | Yes          | Yes        |

- 可以用来修饰什么
	- 可以用来修饰类及类的内部结构: 属性, 方法, 构造器, 内部类
	- 修饰类, 只能使用缺省或者 public

### 2.2 package, import

- package
	- 作用指明该文件中定义的类所在的包
		- 包的作用:
			- 将功能相近的类放在一个包中
			- 可以解决命名冲突的问题
			- 控制访问权限
- import
	- 作用: 导入指定的包 (可以省略当前包和 java.lang 包)
	- java.util.* 表示一次性导入 util 下所有的包
	- import static 组合的使用呢, 调用指定类或接口下的静态的属性或方法

### 2.3 static

- static 的设计思想
	- 设计类时, 类属性不因对象的不同而改变
	- 类方法与调用者无关, 不需要创建对象就可以调用类方法
- 修饰范围: 属性, 方法, 代码块, 内部类
	- 修饰后成员的特点:
		- 伴随着类的加载而加载
		- 优先于对象存在
		- 修饰的成员, 被所有对象所共享
		- 访问权限允许时, 可以不创建对象, 直接被类调用
	- static 方法的注意点:
		- 因为不需要对象就可以调用, 所以 static 方法内部不能有 this 和 super
- 单例模式
	- 两种单例模式
		- 饿汉式

		```java
			public class Ehan{
				private Ehan(){
				}

				private static Ehan ehan = new ehan();

				static Ehan get(){
					return ehan;
				}
			}
		```

		- 懒汉 (多线程优化的)

		```java
			public class Lanhan{
				private Lanhan(){
				}

				private static Lanhan lanhan = null;

				static Lanhan get(){
					if(lanhan == null){
						sychonized(Lanhan.class){
							if(lanhan == null){
								lanhan = new Lanhan();
							}
						}
					}
					return lanhan;
				}
			}
		```

	- 单例模式的应用场景
		- 网站计数器
		- 日志
		- 数据库连接池
		- 读取配置文件的类
		- Application
		- 回收站
		- Task Manager(任务管理器)
- public static void main(String[] args) 方法的理解
	- Java 虚拟机需要调用类的 main() 方法, 所以该类必须是 public 的
	- 因为在执行 main() 时不必创建对象, 所以该方法必须是 static 的
	- String 类型的数组, 是 main 方法在执行时需要传入的参数 (运行模式, 虚拟机参数等)
	- 因为 main 方法是静态的, 所以我们不能在其中直接访问非静态成员, 必须创建一个该类的实例, 才能进行访问.

### 2.4 this, super, override

#### this

- this 是什么
	- 在方法内部使用, 即这个方法所属对象的引用
	- 在构造器内部使用, 则表示该构造器正在初始化的对象
- 什么时候使用
	- 用来区分属性和局部变量
- 在类的构造器中使用 this(形参列表) 中的注意点
	- 在构造器中可以用 this(形参列表) 的方式来调用本类中重载的其他构造器
	- 但在该构造器中不可以通过 this(形参列表) 的形式来调用自身构造器
	- this(形参列表) 必须声明在类的构造器的首行
	- 在一个类的构造器中, 最多只能声明一个 this(形参列表)

#### super

- 作用
	- 用于访问父类中定义的属性
	- 用于调用父类中定义的成员方法
		- 以上两点, 尤其当子类出现父类的同名属性和方法时, 需要特别标注
	- 用于在子类构造器中调用父类的构造器
	- super 的追溯不仅限于直接父类
- 调用父类的构造器
	- 子类的所有构造器默认都会访问父类中的空参数构造器
		- 当父类中没有空参构造器时, 子类的构造器必须通过 this(参数列表) 或者 super(参数列表) 指定调用本类或者父类中相应的构造器, 同时只能二选一, 否则, 将会出现编译出错

| No. | 区别点     | this                                                         | super               |
| --- | ---------- | ------------------------------------------------------------ | -------------------- |
| 1   | 访问属性   | 访问本类中的属性,</br>如果本类中没有此属性则从父类中继续查找 | 直接访问父类中的属性 |
| 2   | 调用方法   | 访问本类中的方法,</br>如果本类中没有此方法则从父类中继续查找 | 直接访问父类中的方法 |
| 3   | 调用构造器 | 调用本类的构造器,</br>必须放在构造器的首行                   | 调用父类构造器,</br>必须放在子类构造器的首行                     |

#### override

- 重写后对方法调用的影响
	- 重写之后, 子类方法将覆盖父类的方法
	- 重写之后, 当创建**子类**对象以后, 通过子类对象调用子父类中的同名同参数的方法时, 实际执行的是子类重写的方法
- 重写的要求
	- 方法名和形参列表需要相同
	- 修饰符
		- 重写方法的权限修饰符不小于父类被重写方法的权限修饰符
		- 子类不能重写 private 方法 (此时不认为是重写方法, 而认为是一个全新的方法, 因为 private 修饰时, 子类不能调用父类的 private 方法)
	- 返回值类型
		- 如果返回值是 void, 则重写方法返回值只能是 void
		- 如果父类返回值是 A 类, 则重写方法可以是 A 类及 A 类的子类
		- 如果父类返回值是基本数据类型, 则重写方法返回值必须是相同的基本数据类型
	- 异常
		- 子类抛出的异常类型不大于父类抛出的异常
	- static 修饰的
		- 要么都声明为 static 的 (已经不是重写了), 要么都不是 static 的 (static 方法是随着类加载而加载的, 不能被重写)

### 2.5 final

- 1. final 修饰类
	- 不能被继承
- 2. final 修饰方法
	- 不能被重写
- 3. final 修饰变量
	- 声明常量

### 抽象类

- abstract 关键字来修饰一个类
	- abstract 来修饰一个方法 → 抽象方法
		- 含有抽象方法的类必须被声明为抽象类
	- 抽象类不能被实例化
	- 不能用 abstract 修饰私有方法, 静态方法, final 方法, final 的类
	- 抽象类中可以有构造器 (需要被子类调用)
- 模板方法设计模式
	- 功能内部一部分是确定的, 一部分是不确定的, 可以将不确定的暴露出去, 交给子类去实现
	- 典型应用:
		- 数据库访问的封装
		- Junit 单元测试
		- Servlet 中 doGet, doPost 方法的调用
		- Spring 中 JDBCTemplate 等

### 接口

- 接口的设计思想
	- 接口的本质就是契约, 标准, 规范. 继承是 ' 是不是 ' 的问题, 接口就是 ' 能不能 ' 的问题
- 接口的特点:
	- interface 来定义 (先写 extends,再写 implents)
	- 接口中所有成员变量都默认是有 public static final 修饰的
	- 接口中所有的抽象方法都默认是 public abstract 修饰的
	- 接口中没有构造器
	- 接口采用多继承机制
- 代理模式 [7. 反射的应用: 动态代理](10_反射,%20动态代理.md#7.%20反射的应用%20动态代理)
- 工厂模式
- Java8 中对于接口的改进
	- 静态方法, static 修饰的方法可以通过接口直接调用
	- 默认方法, default 可以通过接口的实现类进行调用
		- 接口冲突: 如果一个接口中定义了一个默认方法, 另一个接口中也定义了一个同名同参数的方法 (无论是否默认)
			- 解决办法: 实现类必须覆盖接口中同名同参数的方法
		- 类优先原则: 如果一个接口中定义了一个默认方法, 父类中也定义了一个同名同参的非抽象方法, 那么不会出现冲突; 接口中的方法会被忽略.

		```java
			package heaptest;
			public class InterfaceTest {
				public static void main(String[] args) {
					ManMan man = new ManMan();
					man.help();
				}
			}

			interface Xifu{
				default void help(){
					System.out.println("救媳妇");
				}
			}
			interface Laoma{
				default void help(){
					System.out.println("救老妈");
				}
			}
			class ManMan implements Xifu,Laoma{
				@Override
				public void help() {
					Xifu.super.help();
					Laoma.super.help();
				}
			}
		```

### 3.2 类的成员

- 创建 Java 自定义类的步骤
	1. 定义类 (考虑修饰符, 类名)
	2. 编写类的属性 (考虑修饰符, 属性类型, 属性名, 初始化值等)
	3. 编写类的方法 (考虑修饰符, 返回值类型, 方法名, 形参等)
- 类的访问机制
	- 在同一个类中: 类中的方法可以直接访问类中的成员变量.(静态方法不能访问非静态 (JVM 初始化时间不同))
	- 在不同类中, 先创建要访问的类的对象, 再用对象访问类中定义的成员

#### 属性 (field)

##### 语法格式

修饰符 数据类型 属性名 = 初始化值
- 修饰符:
	- 访问权限修饰符 (private, protected, 缺省, public)
	- static, final
- 数据类型:
	- 基础数据类型
	- 引用数据类型
- 属性名
	- 符合命名规范即可

##### 成员变量和局部变量

- 区分:
	- 在方法体外, 类体内声明的变量称为成员变量.
	- 在方法体内部声明的变量称为局部变量.
![[附件/image/00_面向对象__1.jpg]]

- 注意: 局部变量除形参外, 均需显式初始化

|              | 成员变量                         | 局部变量                                 |
| ------------ | -------------------------------- | ---------------------------------------- |
| 声明的位置   | 直接声明在类中                   | 方法形参或内部, 代码块内, 构造器内等     |
| 修饰符       | private, public, static, final 等 | 不能用权限修饰符修饰, 可以用 final 修饰    |
| 初始化值     | 有默认的初始化值                 | 没有默认的初始化值, 必须显式赋值方可使用 |
| 内存加载位置 | 堆空间,或静态域内                | 栈空间                                   |

- 关于局部变量, 有一个在方法中传参的经典问题 swap(int a, int b), 注意交换的是成员变量还是局部变量

#### 方法 (method)

##### 什么是方法

- 方法是行为的抽象, 类似 C 语言的函数
- Java 里方法不能独立存在, 必须定义在类里

##### 如何定义一个方法

```java
修饰符 + 返回值类型 + 方法名(){
	方法的程序代码;
	return 返回值;
}
```

- 注意:
	- 方法中只能调用方法或者属性, 不能在方法中定义方法

##### 方法的重载

- 重载的概念:
	- 在同一个类中, 允许存在一个以上的同名方法, 只要他们的参数个数或者参数类型不同即可
	- 重载与返回值类型无关, 只看参数列表, 且参数列表必须不同 (参数个数或参数类型), 调用时, 根据方法参数列表的不同来区别
- 可变参数的形参
	- 可变参数即在同名方法之间形成重载
	- 可变参数的个数可以是 0 个, 1 个, 或多个
	- 可变个数形参的方法与方法参数部分使用数组是一致的
	- 方法的参数部分有可变形参, 该形参需要方法参数声明的最后
	- 在一个方法的形参位置, 最多只能声明一个可变个数的形参

##### 方法的参数传递

Java 里方法的参数传递方式只有一种, 值传递.(基础值的传递和引用地址值的传递)

#### 构造器 (constructor)

- 构造器的特征:
	- 具有类相同的名称
	- 它不声明返回值类型
	- 不能被 static, final, synchronized, abstract, native 修饰, 不能有 return 返回值
- 构造器的作用: 创建对象, 给对象进行初始化 (init)
- 构造器的分类:(每个类都至少有一个构造器)
	- 隐式 (无参)
		- 默认构造器的修饰符与所属类的修饰符一致
	- 显式 (无参或有参)
		- 一旦定义了显式构造器, 则系统不再提供默认的无参构造器
		- 一个类可以创建多个重载的构造器
- 构造器的注意点
	- 父类构造器不能被子类继承

- 对象属性赋值的先后顺序
	1. 默认初始化 ([[#对象的创建和使用 Java层面]])(clinit)
	2. 显式初始化 ()(init)

	```java
		class Person{
			//这就是显式初始化
			int age = 12;
		}
	```

	3. 构造器中初始化
	4. 通过对象.属性赋值 (get,set 方法等)

#### 代码块

- 静态代码块: 用 static 修饰的代码块
	1. 可以有输出语句。
	2. 可以对类的属性、类的声明进行初始化操作。
	3. 不可以对非静态的属性初始化。即: 不可以调用非静态的属性和方法。
	4. 若有多个静态的代码块,那么按照从上到下的顺序依次执行。
	5. 静态代码块的执行要先于非静态代码块。
	6. 静态代码块随着类的加载而加载,且只执行一次。
- 非静态代码块: 没有 static 修饰的代码块
	1. 可以有输出语句。
	2. 可以对类的属性、类的声明进行初始化操作。
	3. 除了调用非静态的结构外,还可以调用静态的变量或方法。
	4. 若有多个非静态的代码块,那么按照从上到下的顺序依次执行。
	5. 每次创建对象的时候,都会执行一次。且先于构造器执行。

```mermaid
graph TD
 id1(声明成员变量的默认初始化)-→id2(显式初始化, 多个初始化块依次被执行,同级别按先后顺序)
 id2-→id3(构造器再对成员进行初始化操作)
 id3-→id4(通过 对象.属性 或 对象.方法 的方式, 可多次给属性赋值)
```

#### 内部类 (Inner class)

- 一个类的定义位于另一个类的内部
	- 分类
		- 成员内部类 (static 成员内部类和非 static 成员内部类)
		- 局部内部类 (匿名内部类)
	- 作为成员
		- inner class 可以声明为 private 和 protected
		- 可以调用外部类的结构
		- 可以声明为 static 的
	- 作为类
		- 可以在内部定义属性, 方法, 构造器等
		- 可以声明为 abstract 的, 因此可以被其他的内部类继承
		- 可以声明为 final 的
		- 编译以后生成 OuterClass$InnerClass.class 字节码文件 (匿名内部类也会生成)
	- 声明内部类时注意【注意】
		1. 非 static 的成员内部类中的成员不能声明为 static 的， 只有在外部类或 static 的成员内部类中才可声明 static 成员。
		2. 外部类访问成员内部类的成员，需要“内部类.成员 " 或“内部类对象.成员”的方式
		3. 成员内部类可以直接使用外部类的所有成员，包括私有的数据
		4. 当想要在外部类的静态成员部分使用内部类时，可以考虑内部类声明为静态的
- 局部内部类: 在方法或者代码块中声明的类

	```java
	class WaiBu{
		方法(){
			class 局部内部类{

			}
		}

		{
			class 局部内部类{

			}
		}
	}
	```

	- 特点
		- 内部类仍然是一个独立的类，在编译之后内部类会被编译成独立的.class 文件，但是前面冠以外部类的类名和＄符号，以及数字编号。
		- 只能在声明它的方法或代码块中使用，而且是先声明后使用。除此之外的任何地方都不能使用该类。
		- 局部内部类可以使用外部类的成员，包括私有的。
		- 局部内部类可以使用外部方法的局部变量，但是必须是 final 的。由局部内部类和局部变量的声明周期不同所致。
		- 局部内部类和局部变量地位类似，不能使用 public，protected，缺省，private 局部内部类不能使用 static 修饰，因此也不能包含静态成员
	- 如何使用
		- 只能在声明它的方法或代码块中使用，而且是先声明后使用。除此之外的任何地方都不能使用该类
		- 但是它的对象可以通过外部方法的返回值返回使用，返回值类型只能是局部内部类的父类或父接口类型
- 匿名内部类
	- 匿名内部类不能定义任何静态成员, 方法和类, 只能创建一个匿名内部类的实例 (通常为实现一个接口方法的实例)
	- 格式: `new 父类构造器(实参列表)|实现接口(){//实现部分}`

	```java
		Thread t = new Thread(new Runnable(){
			@Override
			public void run(){
				System.out.print("this");
			}
		});
	```

	- 特点
		- 匿名内部类必须继承父类或实现接口
		- 匿名内部类只能有一个对象
		- 匿名内部类对象只能使用多态形式引用

### 3.3 面向对象的三大特性

#### 封装 (封装与隐藏)

- 为什么要封装
	- 为了实现 " 高内聚, 低耦合 "
		- 隐藏一个类中不需要对外提供的实现细节
		- 使用中只能通过事先制定好的方法来访问数据, 限制对属性的不合理操作
		- 便于修改, 增强代码可维护性
- 封装的具体体现:
	- private 方法的内部使用 (不对外暴露方法)
	- 将类的属性私有化, 并通过 get set 方法来获取和设置
	- 单例模式

#### 继承 (extends)

- 为什么要有继承:
	- 继承相同的属性 (field) 和行为 (method)
- 作用
	- 继承减少了代码冗余
	- 有利于功能的扩展
	- 让类与类之间产生联系, 是多态的前提 (或者说是多态思想的一个实现)
- 子类和父类
	- 子类继承父类的方法和属性
		- 继承表现的原理: 当通过子类构造器创建对象时,一定直接或者间接的调用了父类的构造器 (super), 直到 Object 类为止
		- 不能直接访问父类私有的成员变量和方法
	- java 只支持单继承 (不同于多层继承)

#### 多态

- 概念:
	- 编译时类型: 编译时, 看左边
	- 运行时类型: 运行时, 看右边

>对象的多态性: 父类的引用指向子类的对象
>
>Father father = new Son();

这种尤其体现在抽象类和接口类的特性被称为: 向上转型

由 `Father father = new Son()` 展开, 提出一个虚方法的概念

```java
	father.walk();
```

- 虚方法:
	- 在这种情境下, 父类根据赋给它的不同的子类对象, 动态调用属于子类的该方法, 这样的方法在编译期是无法确定的
	- 编译时类型和运行时类型
		- 编译时,father 为 Father 类型, 而 walk 方法的调用时在运行时确定的, 所以调用的是 Son 类的 walk 方法, 这种在编译期不确定的表现被称为***动态绑定***
		- 从编译和运行角度看重载和重写:
			- 重载是在编译期间就绑定了的不同的方法, 被称作早绑定或者静态绑定
			- 重写只有到运行时方法被调用的那一刻, 解释运行器才会确定索要调用的具体方法, 这称为晚绑定或动态绑定
- instanceof 操作符
	- 定义: instanceof 是一个二元运算符, 与加减乘除类似
	- 用法, a instanceof B, 要求 a 必须是 B 的子类所创建的对象 (B 是类名, 如 Object)

### 对象的创建和使用 (Java 层面)

- 对象创建的例子:

```java
class Student{
	int age;
	String name;

	public void eat(){
		System.out.println("大声喊叫")
	}
}

public static void main(String[] args){
	//创建一个对象
	Student stu  = new Student();

	//创建一个匿名对象并调用其方法
	new Student().eat();
}
```

- 对象属性的默认初始化赋值
当一个对象被创建时, 会对其中各种类型的成员变量进行自动初始化赋值, 除了基本数据类型之外的变量类型都是引用类型, 如上面的 Person 及前面讲过的数组

| 成员变量类型 | 初始值                    |
| ------------ | ------------------------- |
| byte         | 0                         |
| short        | 0                         |
| int          | 0                         |
| long         | 0L                        |
| float        | 0.0F                      |
| double       | 0.0                       |
| char         | 0 或写为 '\u0000'(表现为空) |
| boolean      | false                     |
| 引用类型     | null                          |

- JVM 层面的对象创建 [创建对象的步骤(6步)](JVM宋红康_上篇06_Java对象和直接内存.md#创建对象的步骤(6步))
	- 堆: 存放对象的实例 (JVM 规范描述: 所有对象实例以及数组都要在堆上分配 (Hotspot 虚拟机栈上分配))[8. 栈上分配和逃逸分析](JVM宋红康_上篇04_堆.md#8.%20栈上分配和逃逸分析)
		- 结论: 逃逸分析和栈上分配所优化的性能未必能抵消进行逃逸分析的性能损耗, 所以 Hotspot 并没有在对象的内存分配中采取逃逸分析的策略
	- 栈: 栈帧的局部变量表中存放了对象的引用, 可以通过该引用找到堆上的对象实例
	- 方法区: 用来存储已经被虚拟机加载的类模板 (类结构)
