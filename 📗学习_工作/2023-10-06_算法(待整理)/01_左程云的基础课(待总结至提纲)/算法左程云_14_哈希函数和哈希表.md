# 哈希函数的特点

- 常见的哈希函数:
	MD5, SHA1

1. 输入和输出
	1. 输入域无穷大
	2. 输出域有限 (结果不随机)
	3. 不同的输入会产生相同的输出 (哈希碰撞)
	4. 哈希值产生的结果覆盖范围较平均 (离散型好)
	5. 哈希值 % m 即可以产生一个 [0, m - 1 ) 范围的.

# 哈希表的时间复杂度

- N 个数扩容的时间长度为 NlogN
- 单词的平均代价即为 logN
- 单次增删改查, 因为控制链的长度, 可以看做是 O(1)
- 离线扩容技术可以继续加速哈希表的时间复杂度.

# RandomPool 结构

有三个方法 (使用 hash 表的结构设计):
- insert(key)
- delete(key)
- getRandom();

方法:
- 结构:
	- map1(str -> index)
	- map2(index -> str)
	- size;

```java
package class013;

import java.util.HashMap;

/**
 * @author Item
 */
public class Code01_RandomPool {
    public static class Pool<T>{
        private HashMap<T, Integer> keyIndexMap;
        private HashMap<Integer, T> indexKeyMap;
        private int size;

        public Pool(){
            keyIndexMap = new HashMap<>();
            indexKeyMap = new HashMap<>();
            size = 0;
        }

        public void insert(T key){
            if(!this.keyIndexMap.containsKey(key)){
                keyIndexMap.put(key, size);
                indexKeyMap.put(size++, key);
            }
        }

        public void delete(T key){
            if(this.keyIndexMap.containsKey(key)){
                int deleteIndex = keyIndexMap.get(key);
                int lastIndex = --size;
                T lastKey = indexKeyMap.get(lastIndex);
                keyIndexMap.put(lastKey, deleteIndex);
                indexKeyMap.put(deleteIndex, lastKey);
                keyIndexMap.remove(lastKey);
                indexKeyMap.remove(lastIndex);
            }
        }

        public T getRandom(){
            if(this.size == 0){
                return null;
            }
            int randomIndex = (int)(Math.random() * size);
            return this.indexKeyMap.get(randomIndex);
        }
    }
}

```

# 32 位无符号整数的范围是 0~4294967295, 现在有一个包含 40 亿个无符号整数的文件, 所以在该文件中必然包含没有出现过的数, 可以最多使用 1G 内存, 怎么找到所有未出现的数?

- 原问题解: bit 数组即可解决

- 进阶
- 内存只有 3KB, 如何找到一个未出现的数?
- 解: 3KB 的 int[] 能开多大? 3000 / 4 = 750 -> 512 最接近的 2 的某次方, 就申请一个 512 的大小的数组.
- 0~4294967295 一定可以被均分到 512 份中. 每份数字应该有 8388608 个数
- 每个数字都去除 8388608, 在哪个范围中就把那个数组元素 ++, 那么一定有一个格子不足 8388608;
- 再把这 8388608 / 512 , 再分解这一过程. 一定还是有不够的
- 那么这个周而复始的过程一定可以定义出这个数字.
