## Redis 作为缓存工作

### 1. 缓存的特征

计算机系统中有两种缓存
1. CPU 内的末级缓存, 即 LLC, 用来缓存内存中的数据
2. 内存高速页缓存, 即 page cache , 用来缓存磁盘中的数据

![[附件/image/23_Redis作为缓存工作.jpg]]

由此得出, 缓存的特征为, 越底层的缓存
1. 一定比上一级更快
2. 一定比上一级容量更小.

### 2. Redis 作为缓存使用

- 缓存命中: 直接读取数据
- 缓存缺失: 从数据库中读取数据, 并写入缓存.

在开发时, 以上逻辑由业务代码完成, 故 Redis 被称为旁路缓存. 示例代码如下:

```
String cacheKey = “productid_11010003”;
String cacheValue = redisCache.get(cacheKey)；
//缓存命中
if ( cacheValue != NULL)
   return cacheValue;
//缓存缺失
else
   cacheValue = getProductFromDB();
   redisCache.put(cacheValue)  //缓存更新
```

### 3. 缓存的类型: 只读缓存和读写缓存

#### 只读缓存

- 逻辑: 读正常读, 如果需要删改, 就要在后端数据库中 **删改** 后, 在 Redis 也进行 **删除**.
- 好处: 最新的数据都在数据库中.

#### 读写缓存

- 逻辑: 读正常读, 写请求也会在 Redis 中执行, 然后再向后端数据库中写入. 这又分为异步写入和同步写入两种情况.
	- 异步写入: 先在 Redis 中写, 当 Redis 发生淘汰时, 再将淘汰的数据写入后端. 好处, 响应快, 坏处, Redis 宕机则数据丢失
	- 同步写入: 在 Redis 和后端同步写入, 好处, 数据一致性强, 坏处, 响应慢.

## 评论区收获和思考

- 问题: Redis 只读缓存和使用直写策略的读写缓存，这两种缓存都会把数据同步写到后端数据库中, 他们有什么区别?
	- 答: 主要在于修改数据, 只读中, 修改数据在数据库中进行, 并把缓存内的数据删除; 读写缓存中, 缓存和数据库都会修改数据.
