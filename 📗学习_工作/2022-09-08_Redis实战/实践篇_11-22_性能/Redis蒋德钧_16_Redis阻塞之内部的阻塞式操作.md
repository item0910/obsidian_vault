## Redis 阻塞之内部的阻塞式操作

### 1. 根据对象分析内部操作带来的阻塞点

1. 与客户端交互
2. 与磁盘交互
3. 主从节点间交互
4. 切片集群

- 下图是各类对象操作的阻塞点
![[附件/image/16_Redis阻塞之内部的阻塞式操作.jpg]]

### 2. 与客户端交互产生的阻塞点

从图中可以看出, 与客户端分为网络 IO, 增删改查, 数据库操作 (清空)

#### (1) 网络 IO

Redis 采用了 IO 多路复用机制, 所以避免了主线程一直等待连接和请求, 所以网络 IO 不是阻塞的主要因素

#### (2) 增删改查

- 普通操作:
	- 主要看是不是 O(N) 的操作, 涉及集合的范围查询通常为 O(N) 所以**第一个阻塞点就是集合的全量查询和聚合操作**, 例如 HGETALL, SMEMBERS 等.
- 删:
	- 删除键值对的时候, 会在需要释放的内存处插入一个空闲内存快的链表以便后续管理和再分配, 这个过程需要时间, 如果一下子释放了大量内存, 那么就会阻塞线程.
	- 删除 bigkey 的时候, 就会释放大量内存, **这就是第二个阻塞点: 删除 bigkey**
		![[附件/image/16_Redis阻塞之内部的阻塞式操作-1.jpg]]

#### (3) 清空数据库

客户端数据库级别的操作就是清空数据库, 这同样会释放大量内存, 显然会形成**第三个阻塞点: 清空数据库**

### 3. 与磁盘交互时的阻塞点

- RDB 文件生成是采用子进程方式进行的, 所以不会产生阻塞 (fork 子进程时会因为 Redis 实例过大而有阻塞)
- AOF 重写也是由子进程完成的, 也不会有阻塞.
	- 但是, 如果 AOF 日志会根据不同的策略进行落盘保存, 如果设置为同步写回的话, 每次需要 1 - 2 ms, 也会阻塞主线程. 这一点会在后面的文件系统对 Redis 的阻塞中再次提及. **第四个阻塞点, AOF 同步写**

### 4. 主从交互时的阻塞点

- RDB 文件的生成和传输本身都是由子线程完成, 但是当从库收到 RDB 文件后, 会进行清空当前数据库的操作, 会形成**第三种阻塞点, 清空数据库**
- 另外, 加载 RDB 文件的时间与 RDB 文件的大小相关, 所以**第五个阻塞点就是加载 RDB 文件**

### 5. 切片集群时的阻塞点

- 迁移的数据量不大, 而且迁移是渐进式完成的, 所以对主线程阻塞的影响不大.
- 不过当使用了 Redis Cluster 方案, 又迁移 bigkey 的话, 就会造成主线程阻塞, 这会在 33 讲中提到.

> 到这里, 我们总结了 5 大阻塞点, 分别是
> 1. 集合全量查询和聚合操作；
> 2. bigkey 删除；
> 3. 清空数据库；
> 4. AOF 日志同步写；
> 5. 从库加载 RDB 文件。

下面我们探讨如何通过异步线程避免阻塞式操作

### 6. 异步执行操作

#### 什么样的操作可以异步执行

- 关键: 不是关键路径上的操作, 即不需要返回结果的操作
- 典型的关键路径操作: 读操作
所以在我们总结的 5 种可能导致阻塞的操作中, 1, 5 是关键路径上的操作, 2, 3, 4 不是关键路径上的操作. 可以采用异步子线程来执行.

### 如何实现异步子线程机制

Redis 会使用操作系统提供的创建线程的 pthread_create 函数创建三个子线程, 他们分别负责 AOF 日志写, 键值对删除和文件关闭的异步执行.

先给客户端返回执行成功, 然后将任务打包成队列放入队列中, 又各自的子线程负责执行.

![[附件/image/16_Redis阻塞之内部的阻塞式操作-2.jpg]]

- 注意点
	- 异步的键值对删除和数据库清空操作是 Redis 4.0 后提供的功能，Redis 也提供了新的命令来执行这两个操作。
		- 键值对删除：当你的集合类型中有大量元素（例如有百万级别或千万级别元素）需要删除时，建议使用 UNLINK 命令。
		- 清空数据库：可以在 FLUSHDB 和 FLUSHALL 命令后加上 ASYNC 选项，这样就可以让后台子线程异步地清空数据库，如下所示：

		```
		FLUSHDB ASYNC
		FLUSHALL AYSNC
		```

	- 遇到 bigkey 删除时, 建议先用 SCAN 命令每次读取一部分数据, 然后进行删除, 对于 Hash 类型的 bigkey 删除, 可以使用 HSCAN, 获取一部分然后删除, 把压力均分.
	- 对于聚合计算, 建议用 SCAN 命令将数据分批读取, 然后再在客户端进行聚合计算
	- 从库加载 RDB 文件, 因为 RDB 文件的大小和主库实例大小直接相关, 所以把主库的大小控制在 2 - 4 GB 左右, 保证 RDB 文件能较快加载

## 评论区收获和思考

Redis 写操作 (HSET, SET, SADD) 等, 是在关键路径上吗?

答:

1. 集合类操作会因集合是否存在返回结果 1 或 0 , 所以算关键路径, SET 操作返回一直都是 OK, 不算
2. 如果不关心返回值, 就不算关键路径.
3. 如果设置了最大内存, 但是没有设置淘汰, 如果超过了, 会返回 OOM, 所以也算关键路径.

老师的回答:

1. 如果需要等待结果, 那么就算关键路径; Redis 作为内存数据库, 写操作需要完成后才可以执行下一步命令, 所以算是在关键路径上.
2. 写入磁盘一般是 Redis 在服务器写到内核缓冲区就行, 除非执行了同步写, 需要等待完成, 否则一般写入磁盘的不算关键路径
3. 可以在客户端设计异步写, 客户端本身不关心结果, 这样就不算关键路径了.
