## 学习之前: hash 保存汽车的经纬信息有什么问题

### hash 保存: 因为无序, 所以无法范围查询

当我们要储存一个车辆的经纬度时, Hash 的保存方式:

- key : car:location
- value: 116.03, 39.02

问题在于, 可以保存, 但是无法范围查询

### sorted set 的好处

可以根据权重进行查询, 所以思考把经纬度 转化为 score 的保存方式.

## GEO 和自定义数据类型

### 1. GeoHash 的编码方式: 二分区间, 区间编码

把各自的经纬度进行二分编码, 最后组成一个最终编码, 过程:

- 把 `[-180, 180]` 分成 `[-180, 0], (0, 180]`, 如果数据在左, 就用 0 表示, 数据在右, 就用 1 表示
- 以此类推, 进行 N 次编码, 经纬度各获得一个 N 位编码值, 然后把两个位置上的编码组合在一起,
- 116.37 和 39.86 的编码过程

- 这样, 实际把地理空间划分成了一个一个方格
![[附件/image/13_GEO和自定义数据类型-3.jpg]]
我们只要找到实际编码值相近的方格, 就可以找到附近的位置了. 为了避免查询不准确的问题, 我们还可以查询给定经纬度所在的方格周围的 4 个或 8 个方格.

### 2. 如何用命令使用 Geo

1. add
`GEOADD cars:locations 116.034579 39.030452 33`
2. 查询
`GEORADIUS cars:locations 116.054579 39.030452 5 km ASC COUNT 10`

### 3. 自定义数据类型 (了解)

- 关键是要实现自定义 RedisObject
![[附件/image/11_String类型Value的内存开销与保存进集合的转化-1.jpg]]
- 元数据结构:
	1. type: 值的类型
	2. encoding: 编码方式
	3. lru: 最后一次访问时间
	4. refcount: 对象引用计数
	- 所以新的数据结构只需要定义 type 和 encoding
- 如何定义 type:
	- 新建类型文件 newType.h, 定义新类型和底层数据结构
	- 在 Redis 的 server.h 中声明这个新类型
	- 在 Redis 的 object.c 中新增新类型数据的创建和释放
- 如何定义新 type 的操作
	- 新建 t_newType.c 定义 操作函数
	- 在 Redis 的 server.c 中的 redisCommandTable 中关联命令与函数
	- 在 Redis 的 server.h 中声明这个操作 ninsert
