## Redis 之 Redis 的缓冲区

### 1. 客户端输入缓冲区

1. 查看输入缓冲区的情况

```sh
CLIENT LIST
id=5 addr=127.0.0.1:50487 fd=9 name= age=4 idle=0 flags=N db=0 sub=0 psub=0 multi=-1 qbuf=26 qbuf-free=32742 obl=0 oll=0 omem=0 events=r cmd=client
```

重点关注 qbuf 和 qbuf-free 两个参数. 如果后面一个指标很小, 就要引起溢出的注意.

1. 输入缓冲区溢出的原因分析
	1. 客户端写入了 bigkey
	2. Redis 处理数据太慢
2. 解决方案:
	1. 调大输入缓冲区的大小: 不可行, 除非修改源码
	2. 避免阻塞

### 2. 输出缓冲区

1. 输出缓冲区的介绍
	- Redis 为每个客户端设置的输出缓冲区也包括两部分：一部分，是一个大小为 16KB 的固定缓冲空间，用来暂存 OK 响应和出错信息；另一部分，是一个可以动态增加的缓冲空间，用来暂存大小可变的响应结果。
2. 输出缓冲区为什么会溢出
	1. 服务器返回 bigkey 的大量结果
	2. 执行了 MONITOR 命令, 将每个命令都写入输出缓冲区中

		```
		MONITOR
		OK
		1600617456.437129 [0 127.0.0.1:50487] "COMMAND"
		1600617477.289667 [0 127.0.0.1:50487] "info" "memory"
		```

3. 解决
	1. 设置缓冲区大小, 通常设置: 不做设置

		```sh
		client-output-buffer-limit normal 0 0 0	
		```

		  设置订阅客户端的缓冲区大小

		```
		client-output-buffer-limit pubsub 8mb 2mb 60
		```

	2. 避免 bigkey 操作
	3. 避免在线上环境持续使用 MONITOR, 临时可以

### 3. 主从集群中的缓冲区

1. 全量复制时复制缓冲区溢出的结果: 关闭主从复制, 导致全量复制失败
- 解决方案 1:

```sh
config set client-output-buffer-limit slave 512mb 128mb 60
```

解读: 设置主从复制缓冲区的大小为 512mb, 并且保证在 60s 之内接受的数据不超过 128mb, 如果假设一条命令的数据是 1kb, 那么可以接受 2000 条 / s

- 解决方案 2:
因为复制缓冲区的内存开销是所有节点数的总和, 所以要控制节点数量.

1. 增量复制时复制积压缓冲区 repl_backlog_buffer 溢出的结果: 重新开始全量复制
- 解决方案: 设置这个值 [[Redis蒋德钧_06_Redis如何实现主从一致#3 断连了怎么办]]

## 评论区收获和思考

- 客户端需要缓冲区吗?
	- 需要, 可以控制发送速率
	- 可以把消息打包进一个 buffer 发送, 效率高很多, 另外: 客户端可以利用 pipline 批量发送命令以期减少网络 IO
	- 客户端可以在主从故障切换时把请求暂存在缓冲区, 等到恢复

- KAITO: 主从增量同步缓冲区不计算在 Redis 内存中, 所以它即使积压也不会导致触发淘汰机制.
