## 学习之前: Redis 为什么可靠

Redis 具有高可靠性, 是指他少丢失, 少断连.

## Redis 如何保持主从一致

### 1. 主从的运作方式: 读写分离

为了避免共享资源的竞争开销

### 2. 主从如何同步:

1. 第一次同步:
	1. 从库执行 `replicaof  172.16.19.3  6379` , 就实现了认主
	2. 三个阶段:
		1. psync ? -1: `?` 指不知道主库的 runID, `-1` 指第一次同步
		2. 主库响应 FULLRESYNC, 带上主库 ID 和目前的复制进度 offset: 即主库执行 bgsave, 生成 RDB 文件, 从库在接收到 RDB 文件之后, 会先把当前数据库清空 (保持干净)
		3. 期间, 新收到的请求会存在 replication buffer 里面, 再传给从库执行, 至此完成主从同步.
		![[附件/image/06_Redis如何实现主从一致.jpg]]
2. 架构: 主 - 从 - 从, 将生成 RDB 文件时要 fork 出线程的阻塞压力分担到从库上.

### 3. 断连了怎么办

1. 主库会将操作备份写入 repl_backlog_buffer 这个环形缓冲区
2. 当连接恢复之后, 从库会将 slave_repl_offset (断连时的位置) 与主库记录的 master_repl_offset 比较, 并将其中的差距命令同步给从库, 用来写入的 buffer 叫做 replication buffer(专门用于主从同步的 buffer)
3. 如果这个环形缓冲区太小, 就会导致数据丢失或者引发全量同步; 为了避免这一情况, 需要把这个环形缓冲区的大小定为:

	>缓冲空间大小 = 主库写入命令速度 * 操作大小 - 主从库间网络传输命令速度 * 操作大小 , 考虑到实际情况, 通常还要将这个数字 × 2;
	举个例子，如果主库每秒写入 2000 个操作，每个操作的大小为 2KB，网络每秒能传输 1000 个操作，那么，有 1000 个操作需要缓冲起来，这就至少需要 2MB 的缓冲空间。否则，新写的命令就会覆盖掉旧操作了。为了应对可能的突发压力，我们最终把 repl_backlog_size 设为 4MB。

### 4. 建议

- 一个 Redis 实例不要太大, 一般在几 GB 级别比较合适, 这样可以减少 RDB 文件生成和传输的开销.


### 问题 1: 为什么主从复制不用 AOF 呢?

- 1. AOF 传输的是字符, 需要处理逻辑, 而且需要从库实例重新进行命令的执行, 还会涉及命令的反复执行; RDB 传输的是二进制数据, 传输快.
- 2. 从端恢复数据使用 RDB 效率要高于 AOF
- 3. 网友: 对数据丢失不敏感的场景是不用开启 AOF 的, RDB 只有全量同步时才会出发一次快照 (频率较低)
