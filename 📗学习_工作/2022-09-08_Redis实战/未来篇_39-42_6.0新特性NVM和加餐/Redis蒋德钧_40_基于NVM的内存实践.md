## 学习之前: NVM 概念和性能

新型非易失存储 (non-volatile memory) 可以让软件以字节为粒度进行寻址访问. 而且可以持久化.
读延迟大约是 200~300ns，而写延迟大约是 100ns。在读写带宽方面，单根 NVM 内存条的写带宽大约是 1~2GB/s，而读带宽约是 5~6GB/s。当软件系统把数据保存在 NVM 内存上时，系统仍然可以快速地存取数据。

1. 最大的优势:**持久化**
2. 访问速度: **接近 DRAM 内存**
3. 容量: 很大, 单根可以达到**128G**, 我们可以轻松构建 TB 级别的内存
产品: AEP 内存

## 40_ 基于 NVM 的内存实践

### 1. NVM 内存的特性与使用模式

1. Memory 模式
	顾名思义就是把他当大容量内存来使用, 没有启用持久化的功能. 6 根 NVM 每根 512G 内存, 可以获得 3TB 的内存
	服务器仍然需要配置 DRAM 内存, 但这一部分被用于 AEP 的缓存, DRAM 空间对应用软件不可见.
2. APP Direct 模式
	启用了 NVM 的持久化功能, 软件将数据写到 AEP 上时, 就被持久化下来了. 又被称为持久化内存 PM persistent memory

### 2. 基于 NVM 内存的 Redis 实践

1. Memory 模式下使用 Redis 大容量实例
	1. 延迟比 Dram 稍高一点
2. APP direct 模式
	- 当服务器中部署了 PM 后，我们可以在操作系统的 /dev 目录下看到一个 PM 设备，如下所示：

	```
	/dev/pmem0
	```

	- 我们使用文件系统格式化这个设备

	```
	mkfs.ext4 /dev/pmem0
	```

	- 把这个格式化好的设备挂载到服务器的一个目录下

	```
	mount -o dax /dev/pmem0  /mnt/pmem0
	```

	- 此时，我们就可以在这个目录下创建文件了。创建好了以后，再把这些文件通过内存映射（mmap）的方式映射到 Redis 的进程空间。这样一来，我们就可以把 Redis 接收到的数据直接保存到映射的内存空间上了，而这块内存空间是由 PM 提供的。所以，数据写入这块空间时，就可以直接被持久化保存了
	- 因为已经持久化了, 所以宕机也不会丢失数据, 可以快速恢复.
	- 需要评估一下性能能否满足要求. 当不满足时, 可以使用多根内存条来提高带宽; 或者使用切片集群分担压力

## 评论区收获和思考

- 问: 有了持久化内存, 是否还需要主从集群呢?
	- 还是需要的, 用 NVM 只是解决了持久化问题, 使用主从集群能提高性能, 读写分离. 并在主节点故障时提升从节点, 提升可靠性.
